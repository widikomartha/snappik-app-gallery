## Delivered behavior

The finished gallery now offers one complete background ZIP of its published delivery revision. A project-serialized request freezes every supported photo across all folders/pages into encrypted immutable manifest rows, deterministic safe identity-suffixed paths, expected lengths and an ordered digest. Concurrent requests share one module/revision/gate-generation job, with queue insertion and manifest creation in the same PostgreSQL transaction. Closing/reopening the tab restores persisted status. Failed/expired output can be explicitly recreated; a fresh revision or gate generation cannot serve an older ZIP.

Attempts record a unique private key before any provider request. The streaming worker uses a PostgreSQL session advisory lock, a renewed 15-minute lease, persisted progress and current gallery eligibility checks, including a final check under the project lock. Provider adapters resolve inside the claimed attempt, so missing configuration becomes a visible failure. Complete inputs, manifest identity/count/bytes and finalized object length must all agree before readiness. Changed, missing, truncated or surplus input fails the whole attempt. Expiry alone does not deny valid delivery; suspension and independent gallery gates do.

`BoundedZip` isolates entry/footer encoding from the locked ZipStream library, using STORE/ZIP64 and a directory spool that spills after 1 MiB. It calls dependency-internal encoder APIs; dependency upgrades require rerunning the archive integrity/count/large-stream checks. No vendor source is modified. Limiting PHP wrapper read-ahead to each expected input length preserves surplus-byte detection. Source bytes and complete ZIP output are streamed; directory records do not accumulate as a PHP array.

Protected SnapPik download routes support GET, HEAD, single ranges and strong If-Range. Every new request rechecks capability, module/revision/generation, password session, account/project gates, readiness and the exact 24-hour application deadline. Private R2 ranges validate expected total length and a pinned ETag; no object URL or key is returned to the client. Early failures return text without attachment headers; late failures leave an incomplete transfer. The browser owns download completion reporting.

Maintenance runs every minute with a five-minute scheduler overlap-lock expiry. It fails abandoned leases only after obtaining the process lock, tracks cleanup for every attempt, paginates exact-key multipart listings, aborts those uploads and deletes the corresponding object. Other keys, including backup prefixes, are ignored. Failures remain pending for a later run. Expired output is denied before deletion succeeds. A compare-and-swap state update prevents maintenance from overwriting a concurrent recreation. Worker/scheduler supervision and private provider configuration are required operational inputs, not services started by these checks.
